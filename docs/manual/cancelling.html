Chapter 10

Cancelling & Billing Rules

Cancelling a booking isn't the same as deleting it — here's exactly what happens to the charge, how your facility can set that rule for itself, and how to undo a cancellation.

What you'll be able to do

  • Cancel a booking and predict, before you click, whether its charge will stand or drop.
  • Set your own facility's cancellation rule in Settings, separately for before-start and after-start cancellations.
  • Use Admin Mode's three-way choice to waive or keep a charge on a single late cancellation, regardless of the standing rule.
  • Reinstate a cancelled booking, and know why it might fail.
  • Recognize when the app offers a true delete instead of a cancel.
  • Read a cancelled booking's badges on the Project Costs list.

What happens when you cancel a booking

A booking is a record of facility time, not just a calendar entry — see Cancelled vs. deleted. So cancelling one asks a question first: had the booking's start time already passed? What happens to its charge from there follows your facility's own Cancellation Billing Rules — two independent settings, one for cancelling before a booking's start time and one for after, each set to "Charge dropped" or "Charge kept."

  1. Open the booking (from the Calendar or a project's Meetings list) and choose Cancel.
  2. The confirmation dialog tells you, in plain language, whether the charge will drop or stand — reading straight from whichever of the two rules applies.
  3. If its start time has already passed and it carries a charge above zero, Admin Mode can additionally offer a one-off, per-booking choice that overrides the after-start rule just for this cancellation.

Out of the box — before anyone has touched the Cancellation Billing Rules in Settings — the app behaves exactly as it always has: before-start cancellations drop the charge, after-start cancellations keep it. The table below shows those factory defaults; if your facility has changed either setting, read "Charge dropped"/"Charge kept" as whatever you've set it to, not as a fixed rule.

Setting your own cancellation rule

Every facility runs a little differently, so the charge-on-cancellation rule isn't fixed in the app — it's a pair of settings your facility sets for itself.

  1. Open Settings and find the Cancellation Billing Rules card.
  2. Set Cancelling Before Start Time to "Charge dropped" or "Charge kept" — this decides what happens when someone cancels a booking that hasn't started yet.
  3. Set Cancelling After Start Time separately — this decides the default for a booking cancelled after its start time has passed, though Admin Mode can still override it per booking (see below).
  4. Click Save Cancellation Rules. The new rule applies to every cancellation from then on — it does not change bookings you've already cancelled.

🔍 Why it works this way. "The slot was held, so the charge stands" is a reasonable default, but not every facility bills that way — some waive after-start cancellations far more readily, others charge for a no-show even if it's cancelled ahead of time. Making both directions configurable, independently of each other, lets your facility's own policy drive the app instead of the other way around. The factory defaults reproduce the app's original, hard-coded behavior exactly, so a facility that never opens this card sees no change at all.

💡 Tip. These two settings only decide what happens automatically. Admin Mode's three-way choice (next section) still lets an admin waive or keep the charge on any single late cancellation, whichever way the setting is currently pointed.

Admin Mode's per-booking override

🔍 Why it works this way. Once a booking's start time has passed, the facility already held that instrument (and possibly staff) reserved for it — that slot couldn't be given to anyone else. That's exactly why the After Start Time setting defaults to keeping the charge. But a facility's standing rule can't anticipate every individual case, so Admin Mode still offers a one-off exception on a started booking with a charge — the same gate used everywhere else in the app that a billing amount can be overridden (see the group-discount Revoke/Apply control in Booking a Session).

  • Cancel & Waive Charge — the booking is cancelled and its charge is dropped from Project Costs, as if it hadn't been held.
  • Cancel & Keep Charge — the booking is cancelled but its charge still counts, because the slot really was held.

This choice only ever appears for a started booking with a charge above zero — cancelling before the start time always just follows the Before Start Time setting, with no per-booking override.

🧪 Try it. Turn on Admin Mode (Settings → Admin Mode). Load the sample data, find a past booking with a cost above zero, and cancel it — you should see the three-way choice. Try Cancel & Waive Charge, then check the project's Costs card: the row should show as cancelled with its amount struck through and counted as 0.

Reinstating a cancelled booking

A cancelled booking immediately frees up its instrument and staff slots for other bookings — that's the whole point of cancelling it. So if you change your mind and reinstate it, the app has to check that slot is still free before putting it back.

  1. Open the cancelled booking (it appears struck-through/grey on the Calendar, or with a Reinstate option in its editor).
  2. Choose Reinstate.
  3. The app re-checks for conflicts — the same same-instrument / same-staff-member overlap check a brand-new booking goes through (see Conflicts).
  4. If nothing else has taken that slot, the booking is restored and starts blocking it again. If something else was booked into it in the meantime, reinstating is refused with an error explaining the conflict.

🔍 Why it works this way. Cancelling a booking is exactly what makes its slot bookable again — someone else may well have grabbed it in the meantime. Reinstating without re-checking could silently double-book an instrument or a staff member, so the app runs the same conflict check it would for a brand-new booking.

When you get a true delete instead

Occasionally, cancelling offers to delete the booking outright rather than just cancel it. That only happens when the booking is an empty note: no attendees, no instruments, no staff, and no cost recorded against it — there's genuinely no record worth keeping.

⚠️ Careful. A true delete is permanent — there's no undo (see No undo). It's only ever offered when the booking carries nothing to lose.

Any booking that has attendees, instruments, staff, or a cost above zero is cancelled instead, never deleted — that's the whole reason cancelling exists as a separate action from deleting.

How cancelled bookings look in Project Costs

A project's Costs card lists every booking's charge, and marks cancelled ones clearly rather than just removing them:

  • A cancelled booking whose charge was dropped or waived shows a "Cancelled" badge, with its amount struck through and counted as 0 toward the running total.
  • A cancelled booking whose charge still stands shows a "Cancelled · charged" badge, and its amount still counts toward the running total.

This is the same rule the Reports & Utilization screen uses for money, so a project's Costs card and the facility-wide Reports totals never disagree about what's owed.

Service entries are cancelled the same way — with their own dialog

A standalone service entry — billable work logged directly against a project, without going through a booking — follows the same core idea: cancelling one never deletes it, and a charge above zero gets its own waive-or-keep decision. It isn't tied to a start time the way a booking is (a service entry has no schedule slot to hold), so its cancel dialog always asks the waive-or-keep question directly, rather than reading the Before/After Start Time settings above. See Service Entries for the full walkthrough.

Check yourself

You cancel a booking that starts tomorrow and already has a cost of 150 on it. Does the 150 still count?

Its start time hasn't passed, so this follows your facility's Before Start Time setting — dropped by default, unless your facility has changed that setting to keep it. Admin Mode has no effect on a before-start cancellation either way.

Without Admin Mode turned on, can you cancel a started booking and drop its charge?

Only if your facility's After Start Time setting is set to "Charge dropped." With Admin Mode off, a started booking with a charge above zero just follows that setting automatically — by default that means the charge stands, but a facility that has switched the setting to "dropped" will see it dropped even with Admin Mode off. Admin Mode's three-way dialog is what lets you override that setting on a single booking, either way.

Why might reinstating a cancelled booking fail?

Because reinstating re-checks for scheduling conflicts, and something else — another booking using the same instrument or the same facility staff member at an overlapping time — may have taken that slot while the booking was cancelled.
