Chapter 13

Backups, Restore & Exports

Save your data to a file, bring it back, move it to a new computer, and hand out reports without risking the one copy you have.

What you'll be able to do

  • Export a full backup of everything in your tracker, including uploaded files
  • Restore a backup — and know exactly what it will wipe out first
  • Turn on automatic daily backups so you don't have to remember
  • Use a silent backup folder in Chrome or Edge, and re-grant it after a restart
  • Move your data from one computer to another, step by step
  • Export a single project's report, or every project at once, in the right format for the job

Exporting a backup

A backup is a single file that contains your entire tracker — every project, person, instrument, milestone, and booking, plus any files you've uploaded to projects. It's the only way to move your data anywhere, and the only way to protect it against something going wrong on this device.

  1. Open Settings from the sidebar.
  2. Find Export Backup under "Portable Data & Backups."
  3. Click it. Your browser downloads a single file — treat it like any other important document.

🔍 Why it works this way. Your data lives only in this browser on this device — there is no server copy sitting somewhere safe. A backup file is the one thing that exists outside that browser, so it's the only real safety net you have.

💡 Tip. Any file you've uploaded to a project — a PDF, an image, a document — travels inside this same backup file. You don't need to back those up separately, and you can't split them out; restoring the backup brings the files back along with everything else.

Restoring a backup

  1. Open Settings and find Restore from Backup.
  2. Choose the backup file you want to load.
  3. Confirm when asked — this is the moment that matters, read the next warning before you click through it. The confirmation itself mentions the automatic safety copy described below.

⚠️ Careful. Restoring a backup replaces everything currently in your tracker — every project, person, booking, and setting is thrown away and swapped for whatever is in the file you're restoring. There is no merge and no undo. Make it a habit: export a fresh backup of what you have right now, before you restore anything else — even if you're sure you don't need the current data, a thirty-second export costs you nothing and a mistaken restore cannot be undone.

💡 Tip — a safety copy now happens for you automatically. The moment before a restore actually replaces your database, the app downloads its own backup of whatever is currently in your tracker — a file named something like core-facility-pre-restore-backup-2026-09-06.json. It's skipped only when your tracker is already empty, since there's nothing worth saving in that case. This isn't a reason to skip exporting your own backup first — think of it as a second safety net under the one you already have, in case you restore without remembering to export.

🔍 Why it works this way. A restore has to fully swap the database out from under the app, so there's no safe way to keep "a bit of both." Treating restore as all-or-nothing is simpler and far less error-prone than trying to merge two sets of projects and bookings automatically and guessing which one you meant. The automatic pre-restore download exists for exactly the moment someone clicks Restore without having exported first — it means even that mistake still leaves a recovery file sitting in Downloads.

🧪 Try it. With sample data loaded, export a backup. Then go add a throwaway project — call it "Test Delete Me" — and restore the backup you just made. Confirm the throwaway project is gone, and check your Downloads folder for the automatic pre-restore safety copy the app made along the way. This is exactly the safety net you'd rely on for real data.

Automatic daily backup

You don't have to remember to export manually. The tracker can do it for you in the background.

  1. Open Settings and turn on Automatic Daily Backup.
  2. Leave the app open in your browser from time to time — the backup runs roughly once every 24 hours while the tracker is open, and is skipped automatically if there's nothing worth backing up yet.

💡 Tip. Automatic daily backup still produces ordinary downloaded files (unless you also set up the silent folder below) — it's worth occasionally checking your downloads to make sure they're actually landing somewhere, and periodically clearing out old ones.

The silent backup folder

Normally, every backup — automatic or manual — triggers a browser download, landing in your Downloads folder and prompting a save dialog. If you're on Chrome or Edge, you can skip that and have backups written quietly into a folder you choose.

  1. Open Settings and find the Silent Backup Folder option.
  2. Pick a folder on your computer when your browser asks.
  3. From then on, automatic (and manual) backups are written straight into a backups subfolder inside the one you chose, with no download prompt.

⚠️ Careful. This feature only works in Chrome and Edge (or other browsers built on the same engine) — it isn't available in Firefox or Safari, where automatic backups fall back to a normal download instead. Also, the browser can forget the permission after you restart it; if silent backups stop appearing, come back to Settings and click Re-enable to grant folder access again. See this rough edge for more.

Move your data to a new computer

Because your data lives only in this browser, moving to a new computer (or a new browser, or handing the facility off to someone else) means moving the backup file across, not "logging in" anywhere.

  1. On the old computer, open Settings and click Export Backup. This downloads a single file — note where it lands.
  2. Copy that file to the new computer — by USB drive, cloud storage folder, email attachment to yourself, or however you'd normally move a file.
  3. On the new computer, open the tracker in a browser for the first time. If the welcome screen appears, choose Start Fresh (you're about to restore instead) or simply proceed — restoring in the next step will replace whatever is there either way.
  4. Open Settings on the new computer, click Restore from Backup, and choose the file you copied over.
  5. Confirm the restore. Your projects, people, instruments, milestones, bookings — and any uploaded files — now all exist on the new computer, exactly as they were when you exported.
  6. Double-check a project or two to confirm everything came across, then you're free to keep working from the new computer.

🔍 Why it works this way. There's no account and no server in the middle, so there's nothing to "sign into" on the new machine — the backup file is the entire transfer mechanism. See Backups are not sync for why the two computers won't silently stay in step afterward.

⚠️ Careful. After this move, the old computer's copy is now out of date — if you keep entering bookings on the old computer too, the two will drift apart and neither backup will be "the real one" anymore. Pick one computer to be the working copy going forward, or export-and-restore between them every time you switch.

Exporting a single project's report

Open any project's detail page to export a polished report of just that project — useful for sharing progress with a PI, a funding body, or your own records.

FormatBest forWhat's in it
XLSX (spreadsheet)Crunching numbers yourself, importing into other toolsProject details, milestones, team, bookings and their costs, as structured rows and columns
DOCX (Word document)A readable written summary to send someoneThe same information laid out as prose and tables, ready to print or attach to an email
PDFA final, non-editable copy for records or signaturesSame content as the DOCX, fixed in place so it looks the same on any device

💡 Tip. All three formats are generated from the same underlying numbers used in Reports and the project's own cost view, so you never have to worry about one export disagreeing with another.

Export All — the facility-wide report

From the main Projects registry, the Export All button produces one spreadsheet covering every project in the facility at once — handy for a facility-wide review instead of project-by-project.

  1. Open Projects from the sidebar.
  2. Click Export All near the top of the registry.
  3. An XLSX spreadsheet downloads, with every project's details, milestones, and costs as rows you can sort, filter, or pivot in your own spreadsheet program.

🔍 Why it works this way. A single project's report reads best as a document (DOCX/PDF) because there's a natural narrative — "here's this one project's story." A facility-wide export is really a dataset, not a story, so it only comes as a spreadsheet, which is what you'd want to actually analyze it in anyway.

Check yourself

You're about to restore an old backup because you need one record that's in it. What should you do first, and why?

Export a fresh backup of your current data first. Restoring replaces everything currently in the tracker with no merge and no undo — if you don't save today's data first, you'll lose it the moment you restore the old file.

You set up the silent backup folder in Chrome, but a week later you notice no new backups have appeared. What's the likely cause and fix?

Chrome (and Edge) can forget the folder permission after the browser restarts. Go to Settings and click Re-enable to grant access to the folder again.

You want to email a PI a clean summary of their project's progress. Which export format should you pick, and why not the facility-wide Export All?

Export the project as a DOCX (or PDF) from its own detail page — it reads as prose, ready to send. Export All is a facility-wide spreadsheet covering every project, not a readable single-project summary.
